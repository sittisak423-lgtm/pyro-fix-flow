# PYRO Fix Flow — ระบบแจ้งซ่อมออนไลน์ (PYRO ENERGIE)

เว็บแอปแจ้งซ่อม → อนุมัติ → จ่ายงาน → ซ่อม → ยืนยันและประเมิน พร้อมแผน PM, จัดการเครื่องจักร (QR / นำเข้า Excel), แดชบอร์ด และหน้าผู้ดูแลระบบ

| ส่วน | ใช้อะไร |
|---|---|
| หน้าเว็บ (Frontend) | React 18 + TypeScript + Vite — โฮสต์ฟรีบน **GitHub Pages** |
| ฐานข้อมูล / ล็อกอิน / เก็บรูป | **Supabase** (PostgreSQL + Auth + Storage + Edge Function) |
| ความปลอดภัย | สิทธิ์ทั้งหมดบังคับที่ฐานข้อมูลด้วย RLS (Row Level Security — กฎว่าใครอ่าน/แก้แถวไหนได้) และ trigger ไม่ได้พึ่งแค่การซ่อนปุ่มในหน้าเว็บ |

---

## ภาพรวมการติดตั้ง (ทำครั้งเดียว ประมาณ 45–60 นาที)

```
1. สร้างโปรเจกต์ Supabase  →  2. รัน SQL สร้างตาราง  →  3. สร้างบัญชีผู้ดูแลระบบคนแรก
→  4. ติดตั้ง Edge Function ส่งอีเมลเชิญ  →  5. เอาโค้ดขึ้น GitHub  →  6. ตั้งค่า Secrets + เปิด GitHub Pages
→  7. ใส่ URL เว็บกลับไปใน Supabase  →  8. ทดสอบ
```

## ขั้นที่ 4 — ติดตั้ง Edge Function สำหรับส่งอีเมลเชิญผู้ใช้

ฟังก์ชันนี้ทำให้ปุ่ม **"✉ ส่งคำเชิญ"** ในหน้าผู้ดูแลระบบทำงาน (ผู้ใช้ได้อีเมล กดลิงก์ แล้วตั้งรหัสผ่านเอง)

1. เมนู **Edge Functions → Deploy a new function → Via Editor**
2. ตั้งชื่อ function: `invite-user` (ต้องสะกดตรงนี้เท่านั้น)
3. ลบโค้ดตัวอย่าง แล้ววางโค้ดจากไฟล์ `supabase/functions/invite-user/index.ts`
4. กด **Deploy function** (ค่า Verify JWT ให้คงเปิดไว้)

### ⚠️ เรื่องอีเมลที่ต้องรู้
บริการส่งอีเมลในตัวของ Supabase มีไว้ทดสอบเท่านั้น — **จำกัดจำนวนต่อชั่วโมงต่ำมาก และส่งได้เฉพาะอีเมลของสมาชิกทีมในโปรเจกต์ Supabase** ก่อนใช้งานจริงกับพนักงานทั้งโรงงาน ให้ตั้ง SMTP ของบริษัท:

- **Project Settings → Authentication → SMTP Settings → Enable Custom SMTP**
- ใช้ SMTP ของ Google Workspace / Microsoft 365 ของบริษัท หรือบริการอย่าง Resend / Brevo

**ทางเลือกระหว่างยังไม่มี SMTP:** เพิ่มผู้ใช้ในหน้าผู้ดูแลระบบ (เอาติ๊ก "ส่งอีเมลเชิญทันที" ออก) → แล้วไปสร้างบัญชีที่ Supabase **Authentication → Add user** ด้วยอีเมลเดียวกัน ตั้งรหัสผ่านชั่วคราว ติ๊ก Auto Confirm → แจ้งรหัสให้ผู้ใช้ทางช่องทางภายใน

## ขั้นที่ 5 — เอาโค้ดขึ้น GitHub

แนะนำใช้ **GitHub Desktop** (ไม่ต้องพิมพ์คำสั่ง)

1. สมัคร <https://github.com> (ถ้ายังไม่มี) แล้วติดตั้ง <https://desktop.github.com>
2. เปิด GitHub Desktop → **File → Add local repository** → เลือกโฟลเดอร์ `pyro-fix-flow`
   - ถ้าขึ้นว่า "not a Git repository" ให้กด **create a repository** → Name: `pyro-fix-flow` → **Create repository**
3. กด **Publish repository**
   - ชื่อ: `pyro-fix-flow`
   - **Keep this code private**: ติ๊กได้ถ้าบัญชีเป็น GitHub Pro/Team (บัญชีฟรีต้องเป็น Public จึงใช้ GitHub Pages ได้ — โค้ดเปิดเผยได้ไม่มีปัญหา เพราะไม่มีรหัสลับอยู่ในโค้ด และข้อมูลทั้งหมดอยู่หลัง RLS ของ Supabase)

> ไฟล์ `.env.local`, `node_modules`, `dist` ถูกกันไว้ใน `.gitignore` แล้ว จะไม่ถูกอัปโหลด

## ขั้นที่ 6 — ตั้งค่า Secrets และเปิด GitHub Pages

ในหน้า repository บนเว็บ GitHub:

1. **Settings → Secrets and variables → Actions → New repository secret** เพิ่ม 2 ค่า
   - `VITE_SUPABASE_URL` = Project URL จากขั้นที่ 1
   - `VITE_SUPABASE_ANON_KEY` = anon public key จากขั้นที่ 1
2. **Settings → Pages → Build and deployment → Source = GitHub Actions**
3. แท็บ **Actions** → เลือก "Deploy to GitHub Pages" → **Run workflow** (หรือ push อะไรก็ได้ 1 ครั้ง)
4. รอ 1–2 นาทีจนขึ้นเครื่องหมาย ✓ สีเขียว → URL เว็บจะอยู่ในหน้า **Settings → Pages** เช่น
   `https://<ชื่อบัญชี>.github.io/pyro-fix-flow/`

หลังจากนี้ ทุกครั้งที่แก้โค้ดแล้วกด **Push origin** ใน GitHub Desktop เว็บจะอัปเดตเองอัตโนมัติ

## ขั้นที่ 8 — ทดสอบหลังติดตั้ง

1. เปิด URL เว็บ → ล็อกอินด้วยบัญชีผู้ดูแลระบบ
2. เมนู **ผู้ดูแลระบบ → ผู้ใช้งาน** → เพิ่มผู้ใช้ทดสอบ 1 คน (บทบาท "ผู้แจ้งซ่อม") → ส่งคำเชิญ
3. เปิดอีเมลของผู้ใช้ทดสอบ → กดลิงก์ → ตั้งรหัสผ่าน → แจ้งซ่อม 1 รายการพร้อมรูป
4. เพิ่มผู้จัดการซ่อมบำรุง + ช่าง ของสาขาเดียวกัน → ทดสอบอนุมัติ → จ่ายงาน → ปิดงาน → ผู้แจ้งยืนยันและประเมิน
5. เมนู **จัดการเครื่องจักร → ▦ QR** → พิมพ์ QR ติดเครื่อง → สแกนด้วยมือถือ ต้องเปิดหน้าแจ้งซ่อมพร้อมเลือกเครื่องไว้ให้

## กติกาสิทธิ์ที่บังคับในฐานข้อมูล (สรุป)

- ทุกบทบาท **ยกเว้นผู้ดูแลระบบ** เห็นเฉพาะ "สาขาของตน" = สาขาหลัก + สาขาที่ผู้ดูแลระบบเพิ่มให้
- อนุมัติได้: ผู้จัดการแผนก / ผู้จัดการซ่อมบำรุง (ตามบทบาท) + ใครก็ได้ที่ผู้ดูแลระบบมอบสิทธิ์ — ภายในสาขาของตน
- จ่ายงาน/โอนงาน: ผู้จัดการซ่อมบำรุงของสาขา · เปลี่ยนสถานะ/บันทึกอะไหล่: ช่างที่ได้รับมอบหมาย หรือผู้จัดการซ่อมบำรุง
- ยืนยันงาน/ประเมิน: เฉพาะผู้แจ้ง และเฉพาะเมื่อสถานะ "ซ่อมเสร็จ"
- ลบคำขอ = soft delete (ซ่อน กู้คืนได้) โดยผู้ดูแลระบบเท่านั้น · ทุกการเปลี่ยนแปลงถูกบันทึกในไทม์ไลน์อัตโนมัติ (audit log)
- ผู้ดูแลระบบลดสิทธิ์/ปิดบัญชีตัวเองไม่ได้ · ต้องมีผู้ดูแลระบบอย่างน้อย 1 คน · ช่างที่มีงานค้างปิดบัญชี/ย้ายสาขาไม่ได้จนกว่าจะโอนงาน

## รันในเครื่องตัวเอง (สำหรับแก้ไขโค้ด — ไม่บังคับ)

1. ติดตั้ง **Node.js 22 LTS** จาก <https://nodejs.org>
2. ในโฟลเดอร์โปรเจกต์ คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ค่า URL / anon key
3. เปิด Terminal ในโฟลเดอร์นี้ แล้วรัน
   ```
   npm install
   npm run dev
   ```
4. เปิด <http://localhost:5173>

คำสั่งอื่น: `npm run build` (สร้างไฟล์สำหรับ deploy ในโฟลเดอร์ `dist`) · `npm run typecheck` (ตรวจ type)

## ข้อควรรู้ในการใช้งานจริง

- **Supabase แพ็กเกจฟรี** จะพักโปรเจกต์อัตโนมัติถ้าไม่มีการใช้งาน 7 วัน (กด Restore ได้) และไม่มีการสำรองข้อมูลรายวันให้ดาวน์โหลด — ถ้าใช้จริงทุกวันทั้ง 3 สาขา แนะนำแพ็กเกจ Pro
- **พื้นที่เก็บรูป**: รูปถูกย่อเหลือด้านยาว 1280 px ก่อนอัปโหลด (ประมาณ 150–300 KB/รูป) แพ็กเกจฟรีเก็บได้ 1 GB ≈ 4,000–6,000 รูป
- **Realtime**: หน้าจอรีเฟรชเองเมื่อมีการเปลี่ยนสถานะ (และดึงข้อมูลใหม่ทุก 2 นาทีเป็นสำรอง)
- เปลี่ยนชื่อสาขา/แผนกได้ตลอด แต่ **รหัสสาขาเปลี่ยนไม่ได้** เพราะอยู่ในเลขที่ใบแจ้งซ่อมและรหัสเครื่องจักร
